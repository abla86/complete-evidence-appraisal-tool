# Repository governance

This repository is governed as one research-software unit: application code, methodology registry, evidence handling, workflow, documentation, tests and CI must remain consistent.

## Preservation rule
Existing, historical, prototype and legacy components are preserved unless there is a documented technical, security, compatibility, legal or methodological reason to remove them. Visibility in the current UI is not a reason for deletion.

## Methodology rule
Every external appraisal instrument or framework must be identified by exact methodology ID/version, authoritative source, implementation status and applicable study/design scope. Historical versions must remain distinguishable from current versions.

## Verification rule
The repository must not claim that an instrument, build, test suite or scientific method is verified unless the relevant evidence and checks actually exist.

## Workflow rule
Changes to methodology, workflow, data contracts, API, UI, tests or documentation must be reviewed as one connected unit.
